# Java 中文注释规范

按照 JDK 与 Javadoc 惯例生成有信息量、可维护的中文注释。保留 Java 标识符、应用程序编程接口（Application Programming Interface，API）名称、Javadoc 标签和代码字面量的原文；英文术语或缩写首次出现时必须给出中文翻译。

处理公共 API、继承/废弃契约、包/模块文档或系统性审查时，读取 [references/javadoc-rules.md](references/javadoc-rules.md)。准备使用扩展标签、版本相关标签、Markdown 文档注释或运行文档检查时，再读取 [references/version-and-validation.md](references/version-and-validation.md)。简单私有实现注释只需遵循本文件。

## 执行流程

1. 阅读仓库中的 `AGENTS.md`、贡献指南、格式化配置和现有同类代码，优先遵循更严格的项目规则。
2. 从用户请求判断修改边界。用户只要求注释时，不改变运行逻辑、签名、可见性、格式或命名；只有边界确实不清且不同选择会改变结果时才询问。
3. 理解被注释元素的职责、输入、输出、副作用、异常、线程安全、空值约定和边界条件；无法从代码、测试或既有文档确认的信息不得猜测。上下文不足时使用中性描述，不擅自称其为扩展点、适配器、缓存、线程安全组件或其他特定角色。
4. 判断是否需要注释。公共 API、扩展点、复杂契约和反直觉实现应注释；显而易见的 getter、setter、局部赋值和重复代码语义不应机械复述。
5. 按项目使用的 Javadoc 形式编写中文说明，保持摘要可独立概括。标签必须与签名一致，参数、返回值和异常说明应补充契约而非复述名称。
6. 检查英文内容。对有语义的英文术语、缩写和句子补充中文翻译；不要翻译标识符、类型名、注解名、标签名、协议值、路径、命令和代码字面量。
7. 优先运行项目已有的格式化、编译、Javadoc、`doclint` 或文档检查，不自行猜测构建命令。若任务仅改注释，至少检查 diff，确保没有业务代码变化。
8. 报告修改范围、验证结果和无法确认的契约；不要声称未执行的检查已经通过。

## 中文与英文

- 使用简体中文解释职责和契约，语句完整、客观、简洁。
- 每个可独立展示的 Javadoc 注释都必须自行完成术语翻译：首次出现时采用“中文名称（英文全称，缩写）”，例如“Java 虚拟机（Java Virtual Machine，JVM）”。同一条 Javadoc 的后文可只用中文或缩写。连续的普通实现注释可在不产生歧义时沿用邻近翻译。
- 只有英文名称而无通行中文译名时，采用“`英文名称`（中文释义）”，例如“`backpressure`（背压机制）”。
- 保留标识符和代码元素原文。传统 Javadoc 使用 `{@code ...}` 或 `{@link ...}`；JDK 23 Markdown 文档注释可使用反引号；普通 `//`、`/* ... */` 注释直接写原名，不添加无渲染意义的反引号。
- Javadoc 固定语法保持英文，例如 `@param`、`@return`、`@throws`、`{@link ...}`；标签后的自然语言必须是中文。
- 引用英文原文时紧邻提供中文翻译。新编写或正在维护的自然语言不得留下只有英文的段落、标题、TODO 或警告；第三方许可证、版权声明、生成内容和必须逐字保留的外部文本除外。
- 不为翻译而创造错误术语。存在行业通用译法时使用通用译法，并在首次出现处保留英文以消除歧义。

## 注释边界

- 解释“为什么”、契约、约束、权衡和非显然行为，不逐行翻译代码。
- 不编造线程安全、性能复杂度、幂等性、空值、异常或版本承诺。
- 不用注释掩盖错误代码。发现注释与实现冲突时，以可验证行为为依据更新注释，并明确指出潜在代码问题。
- 保留有价值的历史背景，但删除或改写失效、重复、误导性的注释。
- 不给重写方法重复父类文档；契约完全一致时使用 `{@inheritDoc}`，存在差异时只补充差异。
- 不修改生成代码。确需修改时先定位生成源或模板，并说明生成关系。

## 完成检查

- 本次新编写或维护的自然语言以中文为主；每个可独立展示的 Javadoc 都自行提供英文术语和缩写的中文翻译，普通实现注释在连续局部上下文中无歧义；保留内容符合明确例外。
- Javadoc 摘要能够独立概括且能被项目文档工具正确截取，标签顺序统一，标签与签名完全匹配。
- 参数、返回值和异常说明都描述真实契约，没有遗漏、重复、占位内容或无依据承诺。
- 链接、标识符、代码片段和固定 Javadoc 语法保持原样且引用有效。
- 注释没有复述显而易见的代码，也没有超出用户授权修改业务代码。
- 已按项目能力执行格式化、编译或 Javadoc 检查，并如实报告结果。
