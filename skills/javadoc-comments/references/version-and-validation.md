## 先识别项目能力

在引入版本相关语法前，依次检查：

1. 构建文件中的源码级别和目标级别，例如 Maven 的 `maven.compiler.release`、Gradle 的 Java 工具链或 `--release` 参数。
2. 持续集成环境实际使用的 JDK 版本。
3. 同模块现有文档注释形式和标签。
4. 项目是否配置自定义 doclet、taglet、`doclint` 或注释检查插件。

不得仅根据本机 `java -version` 决定源码可以使用的文档语法。

## 按版本选择语法

- 所有常见 Java 版本均可使用传统 `/** ... */` 文档注释和基础标签，如 `@param`、`@return`、`@throws`、`@see`、`@since`、`@deprecated`。
- `@Deprecated` 的 `since` 与 `forRemoval` 元素从 Java 9 开始可用。低版本源码只使用无元素形式 `@Deprecated`。
- `{@summary ...}` 从 JDK 10 开始可用。只有项目源码级别和文档工具都支持时才使用；否则把中文摘要放在独立首段、详细说明从新的 `<p>` 开始，并检查生成文档的摘要表。
- 内联 `{@return ...}` 从 JDK 16 开始可用，且只能位于方法主描述开头。它同时生成摘要和返回值说明，不要再添加块级 `@return`。
- `{@snippet ...}` 从 JDK 18 开始可用。低版本项目继续使用 `<pre>{@code ...}</pre>`，并确保 HTML 与代码转义正确。
- `///` Markdown 文档注释从 JDK 23 开始可用。只在源码级别支持且项目已采用该风格时使用；不要在同一局部区域无理由混用两种形式。
- `@apiNote`、`@implSpec`、`@implNote` 是 OpenJDK 源码常用的扩展标签，不是 Java SE Javadoc 标准标签。只有项目通过 `-tag`、taglet 或既有文档任务明确支持时才使用；否则用普通正文或实现注释表达同一信息。

新增任何版本相关语法时，以项目编译和 Javadoc 任务的实际结果为准。

## 执行校验

按以下优先级验证：

1. 运行仓库已有的格式化、静态检查、Javadoc 或文档聚合任务。
2. 运行受影响模块的编译任务，确认标签引用、源码级别和注解元素有效。
3. 项目提供 Javadoc 任务时启用其既有 `doclint` 设置，检查无效 HTML、缺失标签、错误链接和不可访问引用；同时抽查中文摘要在摘要表中是否被正确截取。
4. 只修改注释时检查 diff，确认没有签名、逻辑、导入或大范围格式变化。

不要绕开项目构建自行拼接一条通用 `javadoc` 命令，因为模块路径、类路径、生成源、自定义 taglet 和访问级别可能不同。

## 处理校验失败

- 先判断失败是否由本次注释修改引起。
- 本次引入的无效链接、标签、HTML 或版本语法必须修复后再交付。
- 若失败来自未修改的代码或环境，保留原始错误摘要，说明已执行的命令和影响，未经用户授权不要扩大修改范围。
- 不通过关闭 `doclint`、删除既有检查或降低构建标准来掩盖问题。
