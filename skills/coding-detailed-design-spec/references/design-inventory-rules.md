# 设计清单与追踪规则

## 标识格式

| 对象 | 格式 | 示例 |
|---|---|---|
| 单个表字段 | `表名.字段名` | `fund_order.order_status` |
| 同表多个字段 | `表名.字段1/字段2` | `fund_order.user_id/order_status` |
| 实体字段 | `实体名.字段名` | `FundOrder.orderStatus` |
| 方法 | `类名.方法名` | `OrderService.createOrder` |
| HTTP 接口 | `HTTP 方法 + 关键路径` | `POST /api/v1/orders` |
| 任务 | `任务类名` | `SmokeTask` |

不同表的字段分别写完整表名。字段定义表保持一行一个字段；组合索引、查询条件、关联键和正文可使用同表多字段简写。未落地名称标注“拟定”。

## 全局引用

统一使用 `<类型><序号>-<对象名称>`：

| 类型 | 示例 |
|---|---|
| 接口 | `API1-CreateOrder` |
| 任务 | `JOB1-SmokeTask` |
| 表/集合 | `DB1-fund_order` |
| 事件 | `EVENT1-OrderCreated` |
| 日志 | `LOG1-CreateOrderStart` |

禁止只写 `API1`、`JOB1` 等裸编号。一个引用只映射一个对象，全文保持一致；模板引用在交付前必须替换。Mermaid 内部节点 ID 使用安全 ASCII ID，完整引用放在显示文本中。

## 最低信息

- 接口：关键路径、入口方法、调用方、输入/输出、主逻辑、成功/失败出口。
- 任务：任务类名、触发方式、扫描/消费范围、主逻辑、重试上限、最终失败处理。
- 表：一个 `DB` 引用对应一个物理表/集合；说明所有者、读写方和表关系。字段或索引仅在新增、变更或影响查询时展开。
- 事件：生产时机、消费方、重复/失败处理。
- 日志：只列关键业务事件、链路字段、级别和敏感信息处理。
- 性能：只列有依据的规模、目标、瓶颈和验证方式；无依据写“待确认”。

## 设计边界

- 每个接口/任务只承担一个核心职责，遵守低耦合、高内聚。
- 跨模块通过 API、事件或明确数据契约交互，不直接访问对方私有表或内部实现。
- 多张表分别建立 `DB` 引用；关系表只说明关联键、读写方向和一致性边界。
- 追踪链保持最短：`业务动作 -> API/JOB -> DB/EVENT -> LOG`。
- 图、清单、正文和汇总数量必须一致。
