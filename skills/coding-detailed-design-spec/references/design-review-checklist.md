# 详细设计审查清单

## 聚焦度

- [ ] 阅读顺序为：实现清单 → 接口/任务主逻辑 → 数据表关系 → 关键约束。
- [ ] 每个接口/任务单元优先不超过一页，仅有一张主流程图、一张主时序图和 3-7 个交互步骤。
- [ ] 背景、请求响应样例和通用安全/日志/性能说明没有重复。
- [ ] 只展开会改变编码、测试、容量或上线方案的内容。
- [ ] 既有逻辑调整只加粗具体变更文字，没有加粗整段、整表或整个章节。

## 主逻辑

- [ ] 接口给出 HTTP 方法、关键路径和 `类名.方法名`；任务给出任务类名和入口方法。
- [ ] 主流程、关键分支、成功出口、失败出口、重试/补偿能直接映射到实现。
- [ ] 流程图和时序图包含实际 Mermaid 源码，引用与实现清单一致。
- [ ] 流程图遵循 `$mermaid-flowchart`，时序图遵循 `$mermaid-sequence-diagram`。
- [ ] 模板示例已按实际业务替换，没有把假设写成事实。
- [ ] 流程图的改动节点使用 `changed` 红色语义类并带“变更”文字；没有复用异常类 `exception`。
- [ ] 时序图的改动消息使用淡红色 `rect` 包裹，并通过 `Note` 或消息文字标明“变更”。
- [ ] 正文、流程图和时序图标记的是同一组改动点；纯新增和未改动逻辑没有被误标。

## 数据表关系

- [ ] 一个 `DB` 引用只对应一个物理表/集合，所有者、读方、写方明确。
- [ ] 多表关系说明关联键、读写方向和事务/最终一致性边界。
- [ ] 单字段使用 `表名.字段名`；同表多字段使用 `表名.字段1/字段2`；不同表分别写完整表名。
- [ ] 字段、索引、生命周期和迁移仅在新增、变更或影响实现时展开。

## 关键约束

- [ ] 安全、异常、一致性、日志和性能合并为关键约束，没有重复大章节。
- [ ] 日志包含关键事件、级别、链路/业务字段和脱敏要求。
- [ ] 性能包含有依据的规模、目标、瓶颈和验证方式；未知项标为“待确认”。
- [ ] 全局引用使用“编号+对象名称”并全文一致，图、表、正文和汇总数量一致。
