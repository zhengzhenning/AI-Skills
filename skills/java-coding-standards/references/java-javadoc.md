# Java 中文注释与 Javadoc 规范

## 基本要求

- 使用 `/** ... */` 编写可生成 API 文档的注释，使用 `//` 或 `/* ... */` 解释实现细节；文档注释放在注解之前并紧邻声明。
- 禁止使用单行 `/** ... */`；所有 Javadoc 必须展开为多行格式，便于后续补充标签、审查和保持统一视觉结构。
- 摘要必须是完整、简洁的中文句子且可独立理解。JDK 10 及以上且项目支持时，可在开头使用 `{@summary ...}`；否则用独立首段，详细说明从新的 `<p>` 开始。
- 使用 `{@code ...}` 表示关键字、字面量和短代码，使用 `{@link ...}` 引用可解析 Java 元素；传统 Javadoc 中用 `{@literal ...}` 或 `{@code ...}` 处理 `<`、`>`、`&`。
- 只描述可验证的公开契约，不猜测线程安全、性能、空值、幂等性或架构角色。

## 覆盖范围

公开或受保护的类、接口、枚举、记录、注解、构造器、方法和字段必须有 Javadoc；扩展点、跨模块契约、`package-info.java`、`module-info.java` 和复杂私有实现也应说明。完全继承父契约的重写方法可使用 `{@inheritDoc}`；生成代码应从生成源维护。

## 信息内容

按调用者视角说明职责、边界、参数范围、格式、单位、时区、空值、返回值语义、空集合与 `null` 的区别、可观察副作用、状态变化、资源所有权、异常触发条件、并发/异步/取消、缓存、重试和性能约束。不要复述 getter、setter 或下一行代码。

## 标签与顺序

标签按项目既有顺序；无既有约定时使用：`@apiNote`、`@implSpec`、`@implNote`（仅项目支持时）→ `@param`（类型参数后普通参数，顺序与声明一致）→ `@return` → `@throws` → `@see` → `@since` → `@serial` 系列 → `@deprecated`。

- 每个类型参数和参数必须有对应 `@param`，说明角色、范围和空值约定。
- 非 `void` 方法必须说明返回语义；构造器和 `void` 方法不得写 `@return`。
- `@throws` 说明调用者可理解的触发条件，不机械复制底层异常。
- 只有确认版本号时才写 `@since`；废弃元素同时使用 `@Deprecated` 与 `@deprecated`，说明原因、替代 API 和迁移方式。
- `@author`、`@version` 仅在项目明确要求时使用；作者、日期、工单号等版本控制系统已可靠记录的信息不得机械写入。
- 项目统一使用 `@exception` 时可以沿用，否则统一使用标准的 `@throws`。

## 元素专项规则

- 类/接口：说明职责、生命周期、协作边界和可验证的线程安全约束。
- 枚举：说明整体概念，为含义不直观的常量补充说明。
- 记录：说明不变量，并为每个组件写 `@param`。
- 注解：说明目标、处理时机、继承/重复规则和默认值。
- 构造器：说明创建后的状态、依赖所有权、参数约束和失败条件。
- 方法：说明正常结果、失败承载方式、异步完成时机和取消语义。
- 字段/常量：说明单位、范围、特殊值、可变性和可见性含义。
- 包/模块：说明职责、入口类型、依赖方向，以及 `exports`、`uses`、`provides` 的必要约束。

## 中文与英文

自然语言以简体中文为主。英文术语首次出现写成“中文名称（English Name，缩写）”，例如“Java 虚拟机（Java Virtual Machine，JVM）”；没有通行译名时使用“`English term`（中文释义）”。保留 Java 标识符、包名、标签、注解、命令、路径、URL、配置键、协议字段、字符串字面量和许可证原文。

## 普通实现注释

注释放在被解释代码之前并保持缩进。解释原因、不变量、兼容限制、竞态规避和排序/资源约束；禁止逐行翻译、复制需求文档、留下只有英文的 TODO/FIXME 或保留过期注释。重写方法契约一致时使用 `{@inheritDoc}`，存在差异时只补充差异。

## 版本与扩展标签边界

- `{@summary}`、内联 `{@return}`、`{@snippet}` 和 `///` Markdown 文档注释必须先确认源码级别、Javadoc 工具和项目既有风格；不支持时使用传统多行 Javadoc。
- `@apiNote`、`@implSpec`、`@implNote` 只有项目通过 `-tag`、taglet 或既有文档任务注册后才能使用；否则使用普通正文或实现注释。
- `{@link}`、`{@linkplain}`、`{@value}` 和 `{@inheritDoc}` 必须引用真实可解析元素；链接失效时先修复引用或改用 `{@code}`，不得保留猜测链接。
- 传统 Javadoc 中必须使用合法 HTML；`<`、`>`、`&` 等字面字符使用 `{@literal}` 或 `{@code}` 转义，不得关闭 `doclint` 掩盖错误。

## 注释审查清单

- 文档注释放在注解之前、声明紧邻位置，并且所有 Javadoc 均使用展开的多行形式。
- 首句是完整中文摘要，可被文档工具独立截取；详细说明从新的 `<p>` 段落开始。
- 类型参数、参数、返回值和异常标签与签名一一对应；构造器和 `void` 方法没有错误的 `@return`。
- 注释描述真实契约，覆盖必要的范围、单位、空值、异常、副作用、异步/取消和资源约束，没有无依据承诺。
- 类、接口、枚举、记录、注解、构造器、公共/受保护方法与字段，以及 `package-info.java`、`module-info.java` 的必要边界均已覆盖。
- 没有逐行复述代码、无主 TODO/FIXME、重复父类文档、无效链接或过期说明；生成代码从生成源维护。
- 纯注释任务的 diff 不包含业务逻辑、签名、可见性或无关格式化变化。

## 最小示例

```java
/**
 * 查询当前有效的账户快照。
 *
 * @param userId 用户唯一标识，不能为 {@code null}
 * @return 查询时刻的只读账户快照
 * @throws IllegalArgumentException 当 {@code userId} 为空字符串时抛出
 */
AccountSnapshot findAccount(String userId);
```
