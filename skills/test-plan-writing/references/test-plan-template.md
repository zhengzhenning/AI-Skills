## 完整示例

### TC-LOGIN-001：正确账号密码登录

- 🚦 验证模式：非灰度（全量登录开关开启）
- 🎯 测试场景：验证已启用用户使用正确账号和密码能够成功登录。
- 🧰 前置条件：测试服务可用；当前会话未登录；准备登录接口访问权限。
- 🗃️ 测试数据：账号 `tester@example.com`；正确密码使用安全存储中的脱敏引用；无需预置业务记录。
- 🧭 测试步骤：
  1. 准备状态为“已启用”的测试账号 `tester@example.com`。
  2. 确认账号不带灰度标识，调用 `POST /api/login`，填写正确密码。
  3. 记录 HTTP 状态码、响应体、用户登录状态及命中的发布范围。
- 💡 测试预期：HTTP 状态码为 `200`；响应 `code` 为 `0`；返回非空 `token`；用户状态为已登录；命中非灰度全量版本。
- 📥 返回结果：HTTP `200`，响应为 `{"code":0,"message":"success","data":{"token":"***已脱敏***","userId":"u10001"}}`；用户状态“已登录”；命中全量版本。
- 📊 测试结果：✅ 通过

### TC-LOGIN-002：错误密码登录

- 🚦 验证模式：灰度（目标用户标签 `灰度组-A`）
- 🎯 测试场景：验证已启用用户输入错误密码时登录被拒绝。
- 🧰 前置条件：测试服务可用；当前会话未登录；准备登录接口访问权限。
- 🗃️ 测试数据：账号 `tester@example.com`，用户标签为 `灰度组-A`；错误密码为一次性测试值 `wrong-password`；执行后移除灰度标签。
- 🧭 测试步骤：
  1. 准备状态为“已启用”的测试账号 `tester@example.com`。
  2. 确认用户命中 `灰度组-A`，调用 `POST /api/login`，填写错误密码。
  3. 记录 HTTP 状态码、响应体、用户登录状态及实际命中版本。
- 💡 测试预期：请求被拒绝；不返回登录令牌；用户保持未登录状态；命中灰度版本。
- 📥 返回结果：⏳ 未执行
- 📊 测试结果：⏳ 未执行
