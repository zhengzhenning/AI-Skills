# 测试计划用例模板

测试用例必须按灰度环境、非灰度环境分章节，不得平铺。每条用例固定包含：`🎯 测试场景`、`🧰 前置条件`、`🗃️ 测试数据`、`🧭 测试步骤`、`💡 测试预期`、`📥 返回结果`、`📊 测试结果`。

编写前先确认：灰度环境测试分支/工作树、非灰度环境测试分支/工作树。任一项未确认时，在文档中保留“待确认”并暂停生成该环境的正式用例，不得猜测分支。

测试数据、测试预期和已执行的返回结果使用代码块展示具体内容。数据量较大时，注明总量、展示范围和省略数量。

用例标题格式为 `### <状态 Emoji> <用例编号>：<用例名称>`，状态与 `📊 测试结果`保持一致：`✅` 通过、`❌` 失败、`⛔` 阻塞、`⏳` 未执行。

同一环境章节内的相邻用例之间使用独立的 `---` 分隔线，分隔线前后各保留一个空行。

## 灰度环境

- 环境归属：灰度
- 测试分支/工作树：`feature/login-gray`（`/workspace/login-gray`）
- 归属基线：`origin/main`

### ⏳ TC-GRAY-001：灰度用户正确登录

- 🎯 测试场景：验证灰度目标用户登录后命中灰度版本。
- 🧰 前置条件：测试服务可用；当前会话未登录；用户已加入 `灰度组-A`；灰度开关开启。
- 🗃️ 测试数据：执行后移除测试用户的灰度标签。

  ```json
  {
    "account": "gray-tester@example.com",
    "password": "***安全存储引用***",
    "grayTag": "灰度组-A"
  }
  ```

- 🧭 测试步骤：
  1. 确认测试用户带有 `灰度组-A` 标签。
  2. 调用 `POST /api/login`，填写正确密码。
  3. 记录响应体、登录状态和实际命中版本。
- 💡 测试预期：用户登录成功并命中灰度版本。

  ```json
  {
    "status": 200,
    "body": {
      "code": 0,
      "data": {
        "token": "<非空字符串>",
        "userId": "u-gray-001"
      }
    },
    "releaseScope": "gray"
  }
  ```

- 📥 返回结果：⏳ 未执行
- 📊 测试结果：⏳ 未执行

## 非灰度环境

- 环境归属：非灰度
- 测试分支/工作树：`test/login-full`
- 归属基线：`origin/main`

### ✅ TC-FULL-001：非灰度用户正确登录

- 🎯 测试场景：验证非灰度用户登录后命中全量版本。
- 🧰 前置条件：测试服务可用；当前会话未登录；用户无灰度标签；全量登录开关开启。
- 🗃️ 测试数据：无需预置业务记录。

  ```json
  {
    "account": "full-tester@example.com",
    "password": "***安全存储引用***",
    "grayTag": null
  }
  ```

- 🧭 测试步骤：
  1. 确认测试用户不带灰度标签。
  2. 调用 `POST /api/login`，填写正确密码。
  3. 记录响应体、登录状态和实际命中版本。
- 💡 测试预期：用户登录成功并命中非灰度全量版本。

  ```json
  {
    "status": 200,
    "body": {
      "code": 0,
      "data": {
        "token": "<非空字符串>",
        "userId": "u-full-001"
      }
    },
    "releaseScope": "full"
  }
  ```

- 📥 返回结果：本次执行得到以下真实返回：

  ```json
  {
    "status": 200,
    "body": {
      "code": 0,
      "data": {
        "token": "***已脱敏***",
        "userId": "u-full-001"
      }
    },
    "releaseScope": "full"
  }
  ```

- 📊 测试结果：✅ 通过
