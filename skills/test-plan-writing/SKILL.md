# 测试计划文档编写

## 核心目标

测试计划只保留两类信息：

1. 可执行的测试用例。
2. 用例执行后的实际返回结果与测试结果。

删除项目背景、排期、环境说明、角色职责、缺陷流程、发布门禁、泛化测试策略等与单条用例执行和判定无直接关系的内容。最多保留一行标题或版本范围用于定位。

## 用例必填字段

每条用例必须按固定顺序写全以下字段，Emoji 与文字名称同时保留：

1. `🚦 验证模式`：明确填写 `灰度` 或 `非灰度`。灰度用例还要说明目标人群/流量标识；非灰度用例说明覆盖全部目标范围或全量开关状态。
2. `🎯 测试场景`：说明验证什么行为及必要条件。
3. `🧰 前置条件`：写明执行前必须满足的条件，例如登录授权、用户角色、服务状态和依赖数据；不写真实密码或令牌。
4. `🗃️ 测试数据`：写明账号、权限、请求参数、业务记录以及灰度标识/非灰度开关等准备与清理方式；敏感值使用脱敏占位符。
5. `🧭 测试步骤`：使用有序步骤写出输入、操作和观察点，确保他人可复现；必须包含验证是否命中目标发布范围的观察步骤。
6. `💡 测试预期`：写出业务行为和发布范围命中情况的可观察、可判定结果。
7. `📥 返回结果`：填写执行时观察到的实际响应、页面提示、状态、灰度命中信息或数据变化；必须直接写在本测试计划文档中，不能只放外部链接。
8. `📊 测试结果`：填写 `✅ 通过`、`❌ 失败`、`⛔ 阻塞` 或 `⏳ 未执行`。

## 编写与回填规则

- 一个用例只验证一个独立行为；正常、异常、边界行为分别成例。
- 灰度与非灰度必须分别设计或明确说明；不能只写“验证发布”，必须验证目标用户/流量是否命中正确版本或开关。
- 步骤和预期是计划内容；返回结果和测试结果是执行事实，不能混写。
- 未执行时，返回结果和测试结果均写 `⏳ 未执行`，不得用预期内容代替实际结果。
- 失败或阻塞时保留实际返回结果，并用一句话说明差异或阻塞原因。
- 返回结果至少记录关键返回码、消息、页面提示、响应字段、状态变化或数据变化；不得只写“符合预期”。
- 不编造实际返回值或执行状态；未知信息写“待确认”。
- Emoji 只作视觉标识，不能单独替代字段名或文字状态。

## 复审检查

复审时只检查以下问题：

- 是否每条用例都有八个必填字段，包括验证模式、前置条件和测试数据。
- 灰度用例是否验证目标人群/流量命中，非灰度用例是否验证全量范围。
- 步骤是否可复现，预期是否可判定。
- 返回结果是否已直接记录在文档内，并与步骤对应。
- 测试结果是否与预期和实际返回结果一致。
- 是否存在背景、流程、指标或链接等无助于执行/判定用例的噪音；有则删除。
