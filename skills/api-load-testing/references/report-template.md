# 压测报告模板

报告分三层，历史与最新并存：

| 层 | 文件 | 组织方式 | 更新规则 |
|---|---|---|---|
| 历史明细 | 每轮结果目录内 `结果摘要.md` | 一轮一报告一目录 | 只增不改 |
| 历史索引 | `RESULTS_ROOT/轮次索引.md` | 每轮一行 | 追加一行 |
| 最新状态 | `RESULTS_ROOT/最新压测报告.md` | 以接口为章节 | 每轮结束更新对应章节 |

单轮报告只写一个接口，混压轮的多接口只用"按接口拆分"一张表；以接口为章节的组织方式只用于 `最新压测报告.md`。三层报告由技能执行者撰写，`run.sh` 不负责。

## 精简原则（先读这条再写报告）

- 只保留决策所需信息，表格优先于段落，未采集指标一行带过。
- 同一行不用分号串联多个事实：一事一行，多项要素用无序列表分层陈述。
- 负载模型等术语统一中文加括号英文：封闭式定并发（constant-vus）、封闭式阶梯并发（ramping-vus）、开放式定吞吐（constant-arrival-rate）、开放式阶梯吞吐（ramping-arrival-rate）。
- 异常分类只列数量大于 0 的类型，全为 0 时整节写"异常：无"。
- 浸泡轮分段只列首段、末段和首个明显恶化段，拐点结论不超过 3 行。
- 篇幅上限：单轮 `结果摘要.md` 正文 ≤50 行，`最新压测报告.md` 每接口章节 ≤30 行。

## 一、结果摘要.md（每轮落盘，单轮明细）

```markdown

- 环境：<环境名 + BASE_URL>
- Token 状态：<有效 / 过期 / 部分失效 / 无需鉴权>（不展示 Token 本身）
- 负载模型：<中文名（executor），如 封闭式定并发（constant-vus）>
- 梯度：
  - warmup：<如 2 VU>
  - 档位：<50 → 100 → 200 VU，各 120s>
- 总时长：<x 分钟>
- 结果目录：<当轮目录绝对路径>

## 2. 每档结果
| 档位 | 请求数 | 失败率 | P95 | P99 | 最大耗时 | 设计内 503 |
|---|---|---|---|---|---|---|
| <档> |  |  |  |  |  |  |

浸泡轮按时间分段，只列首段、末段和首个明显恶化段。

## 3. 异常分类
只列数量大于 0 的类型：<类型：数量>；全为 0 写"异常：无"。

## 4. 拐点结论（梯度轮必填，≤3 行）
<是否出现拐点、位置、依据（吞吐 / P95 相对基线 / 失败率）>；非梯度轮写"本轮不适用"。
```

## 更新规则

1. 每轮结束依次做三件事：当轮 `结果摘要.md` 落盘 → `轮次索引.md` 追加一行 → `最新压测报告.md` 更新对应章节；出现新接口则新增章节。
2. 章节正文永远取该接口最新一轮**有效**压测；若最新轮无效，正文保留上一次有效轮，无效轮追加到历史列表并标注原因。
3. 混压轮只更新"混压/链路"章节，不得改写任何单接口章节。
4. 章节顺序按套件声明的接口清单排列，混压/链路章节固定在最后。
