# 评估提示词（技能迭代回归用）

修改本技能后，依次执行以下三个场景做回归：每个场景在**新会话**中运行，对照检查点逐条核对，任一检查点不过即回改技能。本文件与链路分析执行无关，分析任务不需要读取。

## 场景 A：常规已知入口

前置条件：选一个含明确 HTTP 入口的多模块仓库。

测试提示词：

> 使用 $code-link-tree-analysis 分析 POST /xxx/yyy 的完整调用链，基线分支是 origin/dev。

检查点：

- [ ] Git 版本信息为第一段，含分析分支与基线分支
- [ ] 七段输出齐全且顺序正确
- [ ] 树内跨模块核心方法节点用完整 `模块名::类名.方法名`，并带 `调用方 → 被调用方` 方向
- [ ] 🗄️ / 🔗（💳）/ ❌（⚠️）三类节点带关键词事实（集合+条件 / 接口+时效策略 / 错误码或结果）
- [ ] `文件路径:行号` 只出现在关键证据表格，不在树内
- [ ] 共享子链路用 `[S]` 编号折叠，无重复展开

## 场景 B：基线分支不可确认

前置条件：选一个基线不明确的仓库（或 detached HEAD 状态），执行时不提供基线信息。

测试提示词：

> 使用 $code-link-tree-analysis 分析 GET /xxx/yyy 的调用链。

检查点：

- [ ] 输出停止在 Git 版本信息段，写 `基线分支：待确认`
- [ ] 向用户询问需要补充的分支信息
- [ ] 未输出链路树及后续段落
- [ ] 未把当前分支的上游跟踪分支当作基线

## 场景 C：入口在仓库中定位不到

前置条件：提示词中的接口路径在仓库中不存在。

测试提示词：

> 使用 $code-link-tree-analysis 分析 POST /api/not/exist/path 的调用链。

检查点：

- [ ] 未编造链路树
- [ ] 报告“实现未在仓库中定位”，归入待确认项
- [ ] 简要说明尝试过的定位方式（如 rg 搜索的路由关键字）
