# 语言与框架适配

先识别项目实际语言、版本和框架，再选择本文件对应章节；没有对应章节时只采用语言官方风格和仓库已有惯例，不凭空引入规则。

## Java / JVM

- 遵守项目的 formatter、Checkstyle/SpotBugs/Error Prone 配置；不要用手工格式覆盖工具结果。
- 明确可空性、异常边界和线程安全；资源优先使用自动关闭结构。
- DTO、领域对象、持久化对象和 API 层模型按项目分层，禁止为省代码混用。

## JavaScript / TypeScript

- 以 `tsconfig`、ESLint、Prettier 和运行时版本为事实来源；公共数据边界优先使用显式类型或运行时校验。
- 避免隐式 `any`、未处理 Promise、可变共享状态和不必要的类型断言。
- 浏览器/服务端差异、序列化格式和错误契约必须在边界处明确。

## Python

- 以项目 formatter/linter、Python 版本和类型检查配置为准；公共模块优先保持类型标注和清晰的导入边界。
- 资源使用上下文管理器；异常只捕获能处理的类型，禁止宽泛捕获后继续执行。

## SQL / 数据访问

- 查询参数必须绑定，禁止字符串拼接外部输入；变更语句说明事务、锁和幂等策略。
- 索引、分页、排序和迁移需结合数据规模验证，不能只凭语法检查判断性能。
